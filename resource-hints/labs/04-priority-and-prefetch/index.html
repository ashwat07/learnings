Lab 04 — Priority & prefetch

The browser already assigns a priority to every request. Most of the time it guesses well; the two things it cannot know are which image is the LCP and where the user is going next. That is exactly what fetchpriority and prefetch are for.

Turn on the Priority column in the Network panel (right-click the header row). Everything in this lab is visible there.

Chrome's default priorities

ResourcePriorityNote
HTML documentHighest
CSS in head (render-blocking)Highestpreloading it changes nothing
Font discovered by CSSHighbut discovered late — that's the real problem
Sync script in headHigh
Script with defer/asyncLow
Image, in viewportLow → Highstarts Low, raised once layout proves it's visible
Image, out of viewportLow
fetch() / XHRHigheven for something trivial
fetch(..., {priority:'low'})Lowuse it for analytics and prefetching data
preloadas per aswhich is why as is mandatory
prefetchLowestidle-time only, for the next page

The "Low → High" row is the interesting one: an image's priority is raised only after layout establishes that it is in the viewport, which happens after CSS. That delay is why fetchpriority="high" on the LCP image is one of the cheapest wins available — it skips the wait.
