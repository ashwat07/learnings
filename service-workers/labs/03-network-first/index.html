Lab 03 — Network first & offline

Network-first says: try the network, fall back to the cache. Correct for data that must be fresh. The part everyone leaves out is the timeout — without it, a user on a bad connection waits 30 seconds for a response you already have a copy of.

"Offline" is rare. "Connected to something that never answers" is common, and only a timeout handles it.

Register, reload once, then try the fetch buttons — and then repeat them all with DevTools → Network → Offline.

the offline checklist

  1. Go offline (Network panel) and click fetch /api/data — cached copy, instantly.
  2. Still offline, reload this page — the shell comes from cache.
  3. Still offline, navigate to a page that was never cached — you should get the precached offline page, not the browser's error page.
  4. Go back online and repeat. Everything should return to normal with no further action.
