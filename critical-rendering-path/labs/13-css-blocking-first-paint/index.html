Lab 13 — CSS blocking first paint

CSS doesn't stop the parser — it stops the paint. Which is worse, because a blank screen is what the user sees.

setup

node make-css.mjs
cd ../.. && ./serve.sh
  • 01 · 20 render-blocking stylesheets — plus a 4-deep @import chain and a blocking web font. Record with Screenshots enabled and count the blank frames.
  • 02 · the async-CSS techniques, demonstrated — the media swap and the preload variant, side by side, so you can see them work before you build with them.
  • 03 · your fix — critical CSS inlined under 14KB, everything else async, no @import, font handled without trading FCP for CLS.

the measurement that motivates all of this

Open page 01, then ⌘⇧P → Show Coverage → reload. Read the unused percentage for each stylesheet. Everything in that red bar is bytes the user waited for and never benefited from. That number is the argument for critical CSS — and the reason your extraction has to be automated, because nobody maintains it by hand.
