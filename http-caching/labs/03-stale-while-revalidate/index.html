Lab 03 — stale-while-revalidate

The usual caching trade is fast but possibly stale vs fresh but slow. stale-while-revalidate refuses the trade: serve the stale copy instantly, refresh it in the background, and the next request gets the new content. You buy speed with one request's worth of staleness.

Each run polls the same URL every 800ms for ~12 seconds and bumps the server's content halfway through. Watch two things: the latency bars, and how long the version number takes to catch up.
