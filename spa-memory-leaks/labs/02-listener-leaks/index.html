Lab 02 — Listener leaks

A listener on window or document outlives every component that registered it. It keeps its closure alive, therefore the component, therefore its DOM. And unlike a detached node, it keeps running — so a hundred dead components all react to every scroll.

Select an element and run getEventListeners($0) in the console — that is the fastest listener-leak check there is.

Run A with 50 components, then click "count listeners" and scroll the page.

the patterns, side by side

// ✗ the leak: nothing ever removes this
window.addEventListener('resize', () => this.recompute());

// ~ manual: correct only if the reference is IDENTICAL and every path removes it
const onResize = () => this.recompute();
window.addEventListener('resize', onResize);
// …later, in every unmount path, including error paths:
window.removeEventListener('resize', onResize);

// ✓ AbortController: one signal, any number of listeners, one call to clean up
const ac = new AbortController();
window.addEventListener('resize', () => this.recompute(), { signal: ac.signal });
document.addEventListener('keydown', onKey, { signal: ac.signal });
el.addEventListener('click', onClick, { signal: ac.signal });
// …unmount:
ac.abort();
